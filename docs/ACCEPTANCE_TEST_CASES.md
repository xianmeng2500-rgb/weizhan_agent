## 一、钱包体系（W-01 ~ W-08）

| 编号 | 优先级 | 前置条件 | 测试步骤 | 预期结果 |
|------|--------|---------|---------|---------|

| W-T02 | P0 | A 余额 0 | A 登录 → 会员中心 → 尝试购买会员 | 提示"余额不足，请联系管理员充值"，购买失败，余额不变 🤖 |

| W-T07 | P2 | 超管登录 | 套餐管理 → 停用"签到场次"套餐 | A 端购买场次额度不可用/不可购买；重新启用后恢复 |

## 二、会员体系（M-01 ~ M-05）

| 编号 | 优先级 | 前置条件 | 测试步骤 | 预期结果 |
|------|--------|---------|---------|---------|
| M-T01 | P0 | A 余额 ≥499 | A → 会员中心 → 购买会员 | 扣款 499，余额正确减少；会员状态"生效中"，到期日=今天+365 天；生成购买流水 🤖 |
| M-T02 | P0 | A 会员生效中（剩余 N 天） | 再次购买会员（续费） | 到期日在现有到期日基础上顺延 365 天（不覆盖），扣款 499 🤖 |
| M-T03 | P1 | A 会员过期（可造数：把 end_at 改为昨天） | A → 会员中心 → 购买会员 | 新会员从今天起算 365 天（不从旧到期日累加） 🤖 |
| M-T04 | P0 | A 无会员 | A → 微站管理 → 创建微站 | 弹窗提示"尚未开通会员"，引导前往会员中心，不进入创建页 |
| M-T05 | P0 | A 会员过期 | A → 编辑已有微站（改名/改模块/上传图片） | 后端 403 拦截，前端展示"会员已过期"提示 |
| M-T06 | P0 | A 会员过期 | 浏览器打开 A 的微站 H5 链接 | H5 正常访问、签到正常，不受会员过期影响 |
| M-T07 | P1 | A 会员剩余 7/3/1 天（造数） | A 登录后台任意页面 | 顶部出现黄色到期提醒横幅（含"去续费"按钮），过期后横幅变红色 |
| M-T08 | P1 | A 登录 | 工作台 Dashboard | 显示会员信息卡片：余额、会员状态标签、到期日、剩余场次额度 |
| M-T09 | P2 | A 会员过期后 | 后台读操作：查看微站列表、查看统计、查看表单提交 | 只读操作不受影响（仅写操作被拦截） |

## 三、上线额度体系（C-01 ~ C-07，v1.2：扣减时机=微站上线）

| 编号 | 优先级 | 前置条件 | 测试步骤 | 预期结果 |
|------|--------|---------|---------|---------|
| C-T01 | P0 | A 余额 ≥598 | 会员中心 → 购买上线额度 ×2 | 扣款 598；额度余 2 次；每个额度到期时间=购买日+365 天；流水记录关联 2 个额度 ID 🤖 |
| C-T02 | P0 | A 额度 ≥1，会员生效 | 微站列表 → 对 draft/offline 微站点「上线」 | 微站变 online；额度自动 -1；额度记录标记 used 并关联该微站 ID、记录使用时间；提示"已上线（已消耗 1 个场次额度）" |
| C-T03 | P0 | A 额度 0 | 点「上线」 | 弹窗"场次额度不足（299 元/次）"，引导前往会员中心；微站状态不变；直接调接口返回 403 CREDIT_INSUFFICIENT |
| C-T04 | P1 | A 有 2 个额度：1 个 30 天后过期（造数）、1 个 300 天后过期 | 上线 1 个微站 | 优先扣减"30 天后过期"的那个额度（先到期先扣） 🤖（逻辑层） |
| C-T05 | P0 | A 已上线微站（已扣额度） | 点「下线」 | 微站变 offline；额度**不退还** |
| C-T06 | P0 | A 已下线微站、剩余 1 个额度 | 再次点「上线」 | 再次扣减 1 个额度，微站变 online |
| C-T07 | P1 | A 有未使用额度（造数：expire_at 改为昨天） | 等待定时任务（10 分钟内）或手动触发 | 额度标记 expired，不计入可用余额；会员中心"即将过期"提示正确 |
| C-T08 | P2 | A 会员生效（额度无关） | 签到管理 → 添加/编辑/删除场次 | 全程**不消耗额度**（v1.2 起建场次免费） |
| C-T09 | P1 | A 登录 | 会员中心 → 额度卡片 | 显示"其中 N 个将于 X 天后过期"提示（30 天内） |

## 四、退款（W-08 / 7.7）

| 编号 | 优先级 | 前置条件 | 测试步骤 | 预期结果 |
|------|--------|---------|---------|---------|
| R-T01 | P0 | A 有一笔购买会员流水 | 超管 → 用户详情 → 该流水[退款] | 余额退回 499；会员到期日回退 365 天（若回退后已过期则状态变 refunded） 🤖 |
| R-T02 | P0 | A 购买 2 场额度，已用 1 场 | 对该购买流水退款 | 仅退未使用的 1 场 = +299；已使用的不退；未用额度标记 refunded，余额 0 🤖 |
| R-T03 | P0 | 同一流水已退款 | 再次点击[退款] | 拒绝重复退款，提示"该流水已退款" 🤖 |
| R-T04 | P1 | A 额度全部已使用 | 对该购买流水退款 | 提示"额度已全部使用，无可退金额"，退款失败 |
| R-T05 | P2 | 任意充值流水 | 尝试退款 | 仅购买类流水可退，充值流水无退款按钮/被拒绝 |
| R-T06 | P1 | 完成退款后 | A → 会员中心 | 余额、会员状态、额度余量三处缓存均正确（无脏数据） 🤖 |

## 五、权限控制（7.8 矩阵）

| 编号 | 优先级 | 前置条件 | 测试步骤 | 预期结果 |
|------|--------|---------|---------|---------|
| P-T01 | P0 | super_admin | 创建微站、上线微站、创建场次 | 不受任何会员/额度限制，上线不扣额度，无需购买，不产生扣款 |

| P-T03 | P0 | 子账号 S（父=A，A 会员过期） | S 创建/编辑微站、上线微站 | 被拦截（继承父账号过期状态） |
| P-T04 | P0 | 子账号 S | S → 会员中心 → 购买会员/额度 | 提示"子账号无权购买，请使用主账号购买" 🤖 |
| P-T05 | P0 | admin A | 直接访问 URL `/admin/members`、`/admin/members/1` | 前端路由拦截（仅超管可见菜单和路由）；直接调 `/api/v1/admin/billing/*` 返回 403 |
| P-T06 | P1 | admin A | 侧边栏菜单 | 显示"会员中心"，**不显示**"会员管理"；超管两者都显示 |
